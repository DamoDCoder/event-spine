**A nil pointer panic, not an error.** `Reader.Next` dereferenced a cursor whose
segment was nil, and the process died.

A crash can truncate one segment's unsynced tail while the segment created after
it survives holding nothing — creating a segment syncs the directory, writing to
it does not. That leaves a hole running from the truncation point all the way to
the tail.

`Reader.Next` checks whether the cursor has caught up, finds it has not because
the log's tail is above it, and asks `seek` for the next surviving record.
`seek` correctly finds none: every offset from here to the tail is a gap. It
sets the cursor to nil and returns without error, and `Next` then reads through
it.

The right answer is the one `seek` already knew: nothing at or after this offset
means the reader has caught up, which is `ErrEndOfLog`.

Found by the sweep on its first run with `os` mode in the rotation. The
signature above is recorded as zeroes because the run panics before a clean
probe can be taken; it is filled in once the fix lands.
