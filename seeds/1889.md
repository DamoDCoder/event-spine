**A compaction that returned an error had already taken effect.** One injected
fsync failure, no crash and no corruption: a record acknowledged as durable was
gone, compacted out of a segment by a `CompactAll` that reported failure.

`Compact` swaps the compacted segment in by rename and *then* syncs the
directory. A failure reported by the sync is a failure to make the swap durable,
not a failure to make it: the rename is already visible, and a restart short of
a power cut reads the compacted file. The caller cannot tell the two apart.

This is the same shape as [0072](0072.md) — an operation that reports failure
having already happened — and the same shape as [0017](0017.md) one layer down.
Three times now, which is the argument for stating it as a property of this
design rather than fixing it three more times: **an operation that renames or
writes before it syncs can fail and still have happened.**

Nothing is lost when it does. Compaction only removes records that a newer
record for the same key supersedes, and that invariant is still asserted
unconditionally. What changed is that the harness credits a compaction when it
is attempted rather than when it returns, and `Compact` now says so in its
contract.
