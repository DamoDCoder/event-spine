**This one was the harness, not the log.** Recorded anyway, because a seed that
guards a checker is worth as much as one that guards the code: the mistake it
caught would have made every later compaction failure invisible.

`CompactAll` compacts one segment at a time. When the crash landed inside the
second segment's compaction, the call returned an error — and the workload only
credited `w.compacted` when the whole call succeeded. The first segment had
already been compacted, swapped in by rename, and its directory entry synced, so
its superseded records were legitimately gone. The checker then demanded them
back and reported durable data loss that had not happened.

The fix credits every compaction in the returned slice, since each one in there
finished. Compactions that crashed part way are not in the slice and so license
nothing, which keeps the invariant as strict as it was: a durable record may
only vanish if a compaction that *returned* removed it, and only when a newer
record for its key survives.
