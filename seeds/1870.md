**The harness again, and worth keeping.** A record removed by corruption was
judged by compaction's rule and reported as data loss: `record 43 is gone and no
later record shares its key "acct-00"`.

The checker asks why a durable record is missing, and it asked in the wrong
order. Compaction's case came first, so when a run had both compacted and
suffered a bit flip, a record that corruption had truncated away was held to
compaction's promise — that something newer for its key survives — which
corruption has no reason to keep.

Fourteen of 2,000 swept seeds failed this way, all of them bit flips, none of
them the log. A checker that blames the wrong component is worse than one that
misses: it sends someone to read code that is working, and it teaches everyone
to skim the output.

The order now puts corruption first, and every branch says what it licenses:
corruption licenses a record being *absent* and never a record coming back
*wrong*, which stays asserted for every fault.
