A crash removed an entire segment file, including records whose `Sync` had
already returned. Recovery reported a healthy empty log rather than a loss:
`Open` found no segment files, created a fresh one at offset 0, and returned a
zero `Recovery` — the shape of a log that had never been written to.

The log fsyncs the segment file after appending, which makes the bytes durable,
and never fsyncs the directory that names it. A file whose directory entry has
not been synced does not exist after a power cut, so every acknowledged record
in it went with the entry. This is a POSIX rule the simulated filesystem models
faithfully and the log did not honour: `sim.FS.Crash` keeps only the files whose
directory entry reached `FS.Sync`.

Minimized to: one segment creation, two records, one file sync, one crash at the
next filesystem operation. Crash point 7 of 51 is the first that reproduces, and
every later point in the run reproduces it too, because the missing directory
sync never happens at all.
